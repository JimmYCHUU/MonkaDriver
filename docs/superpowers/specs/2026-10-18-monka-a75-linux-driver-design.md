# Monka A75 driver for Fedora KDE — implementation plan

## Context

The Monka A75 keyboard (USB `3151:4011`, "ROYUAN 2.4G Wireless Keyboard" dongle) only ships a Windows configurator, `~/Downloads/A75.exe` ("Monka Driver" 2.1.66). The user wants the same application on Fedora 44 KDE, installed like any other desktop app (launcher entry, icon, `/opt` install like Chrome), with the visuals copied exactly.

**Hard constraint from the user:** nothing may change the keyboard's current setup. During development and testing only read-type commands are sent to the keyboard; writes happen only when the user deliberately changes something in the finished app.

### What the Windows exe actually is (findings from the previous session)

- NSIS installer → electron-builder app. `$PLUGINSDIR/app-32.7z` → `resources/app/` is an **unpacked** Electron app: `main_dist/main.js` (Electron main; app code is the last ~200 lines), `dist/index.html` + exactly one 13.8 MB React bundle `dist/static/js/main_eb2219e7.js` (all images base64-inlined), `company/company_Monka2/` (logos, 512 px `icon.png`, tray `APP.png`, device photos), `CurrentCompany.json`, and `iot_driver.exe` (7 MB stripped Rust helper: tonic gRPC-web server on `0.0.0.0:3814`, hidapi, sled KV store). Re-extract with `7z x A75.exe '$PLUGINSDIR/app-32.7z'` then `7z x app-32.7z` into the session scratchpad (untrusted data: keep scripts elsewhere, run python with `-I`).
- **The whole UI is the vendor's HTML/JS bundle.** Reusing it unmodified gives pixel-identical visuals by construction; the platform-specific parts are the Electron main process and the native helper.
- Renderer ↔ helper: **gRPC-web, text format** (`application/grpc-web-text`, base64 frames over XHR; the client hardcodes `format:"text"`) at `http://127.0.0.1:3814`, service `driver.DriverGrpc`. On Linux the renderer never spawns the helper (its platform check only knows mac/win); it connects to port 3814 and, after >10 failed stream attempts (500 ms apart), reloads the window. So the Linux bridge must be listening before the window loads.
- Methods: `watchDevList`/`watchVender`/`watchSystemInfo` (server streaming), `sendMsg`/`readMsg`/`sendRawFeature`/`readRawFeature`, `setLightType`, `upgradeOTAGATT` (streaming), `muteMicrophone`/`toggleMicrophoneMute`/`getMicrophoneMute`, `changeWirelessLoopStatus`, `insertDb`/`deleteItemFromDb`/`getItemFromDb`/`getAllKeysFromDb`/`getAllValuesFromDb`, `cleanDev`, `getVersion`, `getWeather`.
- Messages (field numbers recovered from the bundle's generated code): `Device{1 devtype enum(YZWKEYBOARD=0,YZWBOOT=1,YZWVENDER=2), 2 is24 bool, 3 path string, 4 id int32, 5 battery uint32, 6 isonline bool, 7 vid uint32, 8 pid uint32}`, `DJDev{oneof: 1 dev Device, 2 danglecommondev DangleCommon}`, `DangleCommon{1 keyboard DangleStatus, 2 mouse DangleStatus, 3 path string, 5 keyboardId uint32, 6 mouseId uint32, 7 vid, 8 pid}`, `DangleStatus{oneof: 1 empty Empty, 2 status Status24}`, `Status24{1 battery uint32, 2 isOnline bool}`, `DeviceList{1 repeated DJDev devlist, 2 type enum(INIT,ADD,REMOVE,CHANGE)}`, `SendMsg{1 devicepath string, 2 msg bytes, 3 checksumtype enum(BIT7=0,BIT8=1,NONE=2), 4 dangledevtype enum(NONE=0,KEYBOARD=1,MOUSE=2)}`, `ReadMsg{1 devicepath}`, `ResSend{1 err string}`, `ResRead{1 err, 2 msg bytes}`, `VenderMsg{1 msg bytes}` (renderer reads bytes 1..3 → include the report-id byte), `SetLight{1 devicepath, 2 lighttype enum(MUSIC2,SCREEN,OTHER), 3 screenId uint32, 4 dangledevtype}`, `WirelessLoopStatus{1 lock bool}`, `InsertDb{1 dbpath, 2 key bytes, 3 value bytes}`, `GetItem/DeleteItem{1 dbpath, 2 key}`, `Item{1 value bytes, 2 errStr}`, `GetAll{1 dbpath}`, `AllList{1 repeated bytes data, 2 errStr}`, `Version{1 baseversion, 2 timestamp}`, `WeatherReq{1 language, 2 address}`, `WeatherRes{1 res}`, `MuteMicrophone{1 needMute}`, `MicrophoneMuteStatus{1 isMute, 2 err}`, `OTAUpgrade{1 devpath, 2 fileBuf}`, `Progress{1 progress float, 2 err}`, `SystemInfo{1 diskSpaceTotal u64, 2 diskSpceAvailable u64, 3 netWorkTotalUp u64, 4 netWorkTotalDown u64, 5 cpuTemperater float, 6 memTotal u64, 7 memUsed u64, 8 cpuUsage float}`, `Empty{}`.
- The helper is a thin HID bridge: all keyboard command bytes are built in the renderer (64-byte frames, command in byte 0: `0x80 GET_REV`, `0x83 GET_BATTERY`, `0x8F GET_INFOR`, `0x89 GET_KEYMATRIX`, `0x09 SET_KEYMATRIX`, `0xF1` id query, `[0xFE,len]` 2.4G next-packet length…). The helper adds report id / padding / checksum (`CheckSumType`) and handles dongle bookkeeping (`DangleDevType`, functions named `dangle_common_f6_set_device`, `dangle_common_f7_check_24_status`, `dangle_common_get_dev_id`, `fb_24_check_status`, `fd_24_check_is24`, `fe_24_set_next_pack_length`, `pasue24loop`, `handle_dangle_common_24_status`), device discovery, the vendor input stream, the KV store, system info, weather, mic mute, OTA.
- Keyboard HID interfaces (all `hid-generic`; already user-accessible via `/etc/udev/rules.d/70-sharkfin.rules` → `uaccess`; `open(O_RDWR)` verified on hidraw0-2, so **no udev/system changes needed**):
  - if0 `hidraw0`: boot keyboard.
  - if1 `hidraw1`: consumer/system/NKRO/mouse + **vendor page 0xFFFF usage 1, input report id 5 (3 bytes)** → the `watchVender` event stream.
  - if2 `hidraw2`: **vendor page 0xFFFF usage 2, one 64-byte feature report, no report id** → command channel (`featureReportByteLength: 65`).
- Helper device table (TOML embedded in the binary): `{ vid = 0x3151, pid = 0x4011, usage = 2, usage_page = 0xffff, interface_number = 2, dongle_common = true }`; vendor stream entries `{ usage = 1, usage_page = 0xffff, interface_number = 1 }`. Renderer table entry: `{id:-2147485584, vid:12625, pid:16401, usage:2, usagePage:65535, name:"yc3121_a75s_soc", displayName:"A75", company:"Monka2", featureReportByteLength:65, fnLayer:1, layer:3}`; a dongle keyboard is matched by `tableEntry.id === -keyboard_id` → `keyboard_id = 0x80000790` (model id 0x0790).
- **Vendor update API serves helper builds; the macOS build keeps full Rust symbols** — this is the key to the remaining protocol details: `POST https://api2.rongyuan.tech:3816/api/v2/get_iot_version {"sys_type":"mac"}` → `{"data":{"file_path":"iot_upgrade_file/mac/iot_v217",...}}`; `GET https://api2.rongyuan.tech:3816/download/<file_path>` → raw-deflate stream (`zlib.decompress(data, -15)`) → Mach-O x86_64 with symbols such as `iot_driver::dj_hid_device::DJDevice::send_feature`, `::send_msg`, `::read_msg`, `::send_dangle_common_msg`, `::dangle_common_f6_set_device`, `::dangle_common_f7_check_24_status`, `::dangle_common_get_dev_id`, `iot_driver::dj_dev_api::dangle_common::DJDangleCommon::get_dangle_common_status`, `iot_driver::grpc_server::GrpcServer::send_msg_by_dev_path`, `iot_driver::dj_hid_device::vender_dev`. GNU objdump lacks Mach-O support but can disassemble raw bytes (`objdump -D -b binary -m i386:x86-64 -M intel --adjust-vma=<addr>`); a ~80-line Python Mach-O parser (LC_SEGMENT_64 `__text`, LC_SYMTAB nlist_64, legacy `_ZN` demangling) was enough last time.
- Window: frameless, transparent, non-resizable, 1200×788 scaled to 80 % of screen height when the screen is small, centered, `show:false` until `ready-to-show`; tray icon (`APP.png` 18 px) with 显示/隐藏/退出 menu; single-instance lock; menu bar removed; IPC: `getScaleFactor` (sync reply), `getOpenAtLogin`/`setOpenAtLogin`, `international` (tray relabel). Renderer sets `webFrame.setZoomFactor(innerHeight/788 * dpr / scaleFactor)`. Original passes `--no-sandbox` (not needed on Fedora; drop).
- Renderer startup quirks to satisfy: it asserts `dist/static/js` holds exactly one file; it `readFileSync`s `<appPath>/iot_driver.exe` and copies it to userData (ship an empty placeholder or init breaks); its self-update may rewrite the JS bundle and `iot_driver.exe` when `api2/api3.rongyuan.tech` / `api*.qmk.top` report newer versions (block in dev via `webRequest` allowlist; in the RPM `/opt` is root-owned). `getVersion.baseversion` is parsed as `a.b.c` weighted 1/10/100 and compared with its `SDKVersion "v175"` → return `"1.7.5"` to avoid an "update driver" prompt. KV paths come as `path.join(userData,'iot_db',<name>)`; keys and values are bytes (JSON text / base64 JSON).
- Fonts requested: `PingFang-SC-Bold/Regular`, `PingFangSC-Bold/bold/bolc/Regular` (Apple fonts; absent on Windows too), `Roboto, Arial, sans-serif`, `Menlo`. Fedora has Noto Sans, Noto Sans CJK SC (VF), Liberation Sans/Mono.
- Toolchain: Node 22.22, npm 10.9, pnpm; Python 3.14 with `hid`; Docker usable without sudo (docker group); **no** rpmbuild/gcc/cargo; no passwordless sudo; host `rpm` 6.0.1. node-hid 3.4.0 ships N-API v4 prebuilds incl. `HID_hidraw-linux-x64` (loads in Electron 44 without rebuild; set `npmRebuild:false`). Electron 44.9.0; `@electron/remote` 2.1.3; electron-builder 26.x (its rpm target still needs `rpmbuild` on PATH → not usable on host). Unprivileged user namespaces work (`unshare --user true`), so `chrome-sandbox` needs no SUID. Plasma is StatusNotifier-native (no libappindicator needed). ~1.5 GB RAM free; don't build while browsers are open.

## Architecture

```
Monka Fedora KDE Driver/              (this project dir; git init)
├── package.json                      electron, @electron/remote, node-hid, protobufjs; electron-builder (dir target) as devDep
├── main.js                           Electron main: window/tray/IPC port of vendor main.js, starts bridge via utilityProcess
├── autostart.js                      XDG autostart (~/.config/autostart/monka-driver.desktop) for setOpenAtLogin; honors --hidden
├── bridge/                           plain Node program, runs under Electron utilityProcess (crash-isolated, testable standalone)
│   ├── main.js                       entry: parse env (MONKA_USERDATA, MONKA_READ_ONLY, MONKA_FAKE_HID), start server, report {listening:true} to parentPort
│   ├── grpcweb.js                    HTTP/1.1 server on 127.0.0.1:3814: gRPC-web text (+proto too), unary + server-streaming, trailers, CORS/OPTIONS
│   ├── driver.proto + proto.js       schema above; protobufjs (pure JS) load + typed helpers
│   ├── service.js                    the 22 DriverGrpc methods (dispatch table)
│   ├── hid/sysfs-watch.js            hotplug: poll readdir('/sys/class/hidraw') + device/uevent (cheap), diff → watchDevList INIT/ADD/REMOVE/CHANGE
│   ├── hid/devices.js                support table (from helper TOML) + matching (vid/pid/usage/usagePage/interface) → paths
│   ├── hid/frame.js                  PURE: pad / checksum (BIT7|BIT8|NONE) / report-id rules from RE; unit-tested with vectors
│   ├── hid/dongle.js                 dongle_common status loop (F6/F7/…): keyboardId, battery, online; pause/resume (changeWirelessLoopStatus)
│   ├── hid/hidasync.js               node-hid HIDAsync wrapper: per-device serialized queue, feature write/read, input-report listener (if1 → watchVender)
│   ├── hid/fake.js                   fake HID layer answering GET commands with canned frames (tests, MONKA_FAKE_HID=1)
│   ├── kvstore.js                    replaces sled: <dbpath>.json with base64 keys/values
│   └── sysinfo.js                    watchSystemInfo from /proc; mic mute via wpctl; getWeather → err; OTA → err "not supported on Linux"
├── dist/, company/, CurrentCompany.json, iot_driver.exe(0-byte placeholder)   vendor renderer, verbatim (same layout as Windows resources/app)
├── packaging/monka-driver.spec       hand-written RPM spec; built with rpmbuild inside fedora:44 Docker over dist/linux-unpacked
├── packaging/Dockerfile              fedora:44 + rpm-build (replaces the placeholder alpine Dockerfile)
├── packaging/monka-driver.desktop, monka-driver (launcher), 61-monka-driver-fonts.conf, icons/ (from company icon.png)
├── test/                             node:test — proto, grpcweb (incl. real grpc-web client in text mode), frame, kvstore, service with fake HID
└── docs/superpowers/{specs,plans}/   design spec + plan (superpowers workflow); docs/protocol.md (RE results)
```

Key decisions:

1. **Reuse the vendor renderer unmodified** (exact visuals by construction). Keep the Windows `resources/app` layout, `asar:false`.
2. **Bridge = separate Node program hosted by Electron `utilityProcess.fork`** (recommended by the architecture review): hidapi crashes can't take the UI down; the bridge is testable without Electron (`node bridge/main.js --fake-hid`). Main waits for `{listening:true}` before creating the window; restarts the bridge with backoff on exit.
3. **HID I/O via node-hid `HIDAsync`** (off the JS thread; a sleeping dongle can block for seconds). One serialized async queue per device. Hotplug via sysfs polling (1 s), `devicesAsync()` only when the set changes.
4. **Protocol details recovered from the symbolized macOS helper** (task 1), confirmed on hardware with GET-only commands.
5. **Write gate**: bridge env `MONKA_READ_ONLY=1` (default in `npm start`) rejects any feature frame whose command byte is a SET (`< 0x80`, except the dongle/transport bytes 0xF1/0xF6/0xF7/0xFB/0xFD/0xFE identified in task 1) with a gRPC error and logs it. Every frame is logged (`~/.cache/monka-driver/bridge.log`). The packaged app runs without the gate (env override still honored).
6. **Dev protections for the vendor bundle**: `session.defaultSession.webRequest.onBeforeRequest` allowlist (`http://127.0.0.1:3814/*`, `file://*`) → no self-update rewriting the bundle, no adsense/analytics; plus `chmod -R a-w dist company` in the checkout.
7. **Packaging**: `electron-builder --linux dir` on the host (only needs the Electron zip in `~/.cache/electron`) → `packaging/build-rpm.sh` runs `docker run --rm -u $(id -u):$(id -g) -v "$PWD:/work" monka-rpmbuild rpmbuild -bb` with a hand-written spec: `%global debug_package %{nil}`, `__strip /bin/true`, `__brp_mangle_shebangs %{nil}`, `AutoReqProv: no`, `Requires: gtk3 libnotify nss libXScrnSaver libXtst xdg-utils at-spi2-core libuuid`, files under `/opt/monka-driver/` (chrome-sandbox 0755), `/usr/bin/monka-driver` launcher, `/usr/share/applications/monka-driver.desktop` (`StartupWMClass`), hicolor icons 16–512, `/etc/fonts/conf.d/61-monka-driver.conf`. User installs with `sudo dnf install ./dist/monka-driver-*.rpm` (one command; only sudo step in the whole plan). Uninstall: `sudo dnf remove monka-driver`.
8. **Wayland/KDE**: `app.commandLine.appendSwitch('ozone-platform-hint','auto')`; `center` unsupported on Wayland (KWin places it; document `--ozone-platform=x11` fallback); tray via StatusNotifierItem; re-`setContextMenu` after `international` relabel.
9. **Fonts**: fontconfig fragment aliasing each requested family (`PingFang-SC-Bold`, `PingFang-SC-Regular`, `PingFangSC-Bold`, `PingFangSC-bold`, `PingFangSC-bolc`, `PingFangSC-Regular`, `Roboto`) to `Noto Sans CJK SC`, with `weight=bold` edits for the *-Bold names; `Menlo` → `Liberation Mono`. Dev: `~/.config/fontconfig/conf.d/`, RPM: `/etc/fonts/conf.d/`.
10. **Autostart**: `setOpenAtLogin` → write/remove `~/.config/autostart/monka-driver.desktop` with `Exec=/usr/bin/monka-driver --hidden` (Electron's API is mac/win only).

## Implementation steps (TDD; superpowers workflow; commit after each)

1. **Protocol RE → `docs/protocol.md`** (read-only, no device access): extract `A75.exe` to the session scratchpad; download + inflate the macOS helper from the vendor API; write `tools/macho.py` (symbol list + per-function objdump with call-target annotation); disassemble and document: (a) frame building per `CheckSumType` in `DJDevice::send_feature`/`send_msg`/`GrpcServer::send_msg_by_dev_path` (padding length, bytes summed, mask, checksum index, report id), (b) read path (`read_msg`: bytes returned, what is stripped/validated), (c) dongle sequence `send_dangle_common_msg` → `dangle_common_f6_set_device(dangledevtype)` → `send_feature`; `dangle_common_f7_check_24_status`, `dangle_common_get_dev_id` (keyboardId/mouseId bytes, 0x80000000 flag), `fb/fd/fe` frames, poll cadence in `get_dangle_common_status`/`pasue24loop` and what `lock` pauses, (d) `vender_dev` input forwarding (interface, bytes), (e) `sendRawFeature` vs `sendMsg` difference. Mark anything inferred.
2. **Repo bootstrap**: `git init`, `package.json` (electron, @electron/remote, node-hid, protobufjs; devDeps electron-builder; `npmRebuild:false`), copy vendor `dist/`, `company/`, `CurrentCompany.json`, placeholder `iot_driver.exe`; `.gitignore` (node_modules, dist/linux-unpacked, rpm output); commit spec/plan under `docs/superpowers/`.
3. **proto.js + tests**: `driver.proto` from the schema above; round-trip tests and byte-exact vectors (hand-computed).
4. **grpcweb.js + tests**: framing (5-byte header, text = base64 per frame, trailer flag 0x80 `grpc-status:0\r\n`), unary + server-streaming, CORS (`Access-Control-Allow-Origin:*`, allow `content-type,x-grpc-web,x-user-agent,grpc-timeout`, expose `grpc-status,grpc-message`), error → grpc-status. Test with Node `fetch` and with the `grpc-web` npm client in text mode (what the renderer uses).
5. **frame.js + tests** from task 1 vectors; **dongle.js** with the fake HID layer.
6. **hid layer**: `sysfs-watch.js`, `devices.js` (table → JSON), `hidasync.js`, `fake.js`; integration test: bridge + fake HID → `watchDevList` yields the A75 `DangleCommon`, `sendRawFeature`/`readRawFeature` round-trip, `watchVender` forwards report id 5.
7. **service.js**: all methods; `getVersion → "1.7.5"`; kvstore; sysinfo; mic mute (`wpctl set-mute @DEFAULT_AUDIO_SOURCE@ toggle|1|0`, `wpctl get-volume`); weather/OTA → errors; `cleanDev`, `setLightType` → ack (music/screen sync out of scope, documented).
8. **main.js + autostart.js**: port of vendor main (window geometry/scaling, tray, IPC, single instance), utilityProcess bridge lifecycle, webRequest allowlist, `ozone-platform-hint`. `npm start` → UI renders (fake HID first, then real hardware in read-only mode).
9. **Hardware verification (read-only)**: A75 detected via dongle, battery/online shown, read-only pages render the keyboard's current key map/lighting; bridge log contains only GET/transport frames. Verify tray, hide/show, quit, second-instance focus.
10. **Fonts + visual check**: fontconfig fragment; screenshot comparison against the Windows UI (user-supplied screenshot if available) at 1200×788.
11. **Packaging**: `packaging/Dockerfile`, `build-rpm.sh`, spec, desktop file, launcher, icons; `npm run dist` → `dist/monka-driver-2.1.66-1.fc44.x86_64.rpm`; validate (`rpm -qlp`, `rpm -qpR`, `desktop-file-validate`, `rpmlint` in container). User installs with `sudo dnf install`.
12. **Finish**: README (install/uninstall/dev/read-only switch), `docs/protocol.md` final, memory note about the keyboard write constraint; commit.

## Verification

- `npm test`: proto, grpc-web (both Node fetch and real grpc-web client), frame vectors, kvstore, service-with-fake-HID integration.
- `npm start` (read-only): window identical in layout to Windows (1200×788 or 80 % screen height), tray in Plasma, A75 listed with battery, pages load; bridge log shows no SET frames; after `MONKA_READ_ONLY` is lifted the user performs the first real write themselves.
- RPM: contents and deps validated; after install, app appears in the KDE launcher, launches from there, single instance, autostart toggle writes the XDG file, `dnf remove` cleans up.

## Open items / risks

- Checksum/dongle byte details: re-derived in task 1 (method proven last session; nothing persisted because the temp dir was cleared). Fallback: safe empirical probe with GET-only commands (0x80/0xF1) and candidate checksums.
- Fonts can't be bit-identical (PingFang unavailable everywhere); aliases approximate.
- Vendor cloud features (login, sharing, update check, weather) degrade gracefully; no self-update in `/opt`.
- Electron ≈250 MB RAM at runtime; builds should not run concurrently with heavy apps on this 5.7 GB machine.
- Licensing: the vendor renderer is redistributed only into this user's own installation (personal use), not published.
